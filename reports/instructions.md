# How to Complete the Weekly Status Report

Start from `template.md` and save a copy for each reporting period. Replace every bracketed prompt with current information, then remove any unused example rows.

## 1. Set the Report Details
- Enter the project name, reporting period, and the preparer's name or role.
- Use the same week boundaries each time and include the year in dates.
- Choose one overall status:
  - **Green:** Work is on track; no material issue threatens agreed scope, schedule, or outcomes.
  - **Amber:** A risk or variance needs attention, but a credible mitigation or recovery plan exists.
  - **Red:** A committed outcome is likely to be missed or is blocked, and stakeholder action or a revised plan is needed.

## 2. Write the Executive Summary
In 2-4 sentences, state what changed this week, whether the project remains on track, and the most important impact or ask for stakeholders. Lead with the outcome, not a list of activities. Make sure the summary agrees with the overall status.

## 3. Record Progress and Next Steps
- List completed outcomes under **Progress This Week**. Prefer delivered milestones or measurable results over effort descriptions.
- List the next week's highest-priority deliverables under **Planned for Next Week**. Include a target date when it helps clarify expectations.
- Keep each bullet specific and concise. If no meaningful progress occurred, state that and explain why.

## 4. Document Risks and Blockers
For each material item, describe the risk or blocker, its impact, the next mitigation action, one accountable owner, and a target date. Use High, Medium, or Low consistently for impact. Raise items that need stakeholder help; do not hide a risk because its mitigation is still being worked out. If there are none, write `None` and remove the sample row.

## 5. Capture Decisions Needed
Include only decisions that require a stakeholder or named decision owner. State the date needed and what may happen if the decision is delayed. If no decision is needed, write `None` and remove the sample row.

## 6. Update Metrics and Milestones
Use a small set of relevant measures. Include the current value and an agreed target or due date, and add brief context for any variance. Do not invent targets; write `Not set` when one has not been agreed.

## 7. Add Stakeholder Notes
Use this section for material context not already covered, such as a dependency or a scope change. Avoid repeating the summary. Write `None` if there is nothing additional.

## 8. Final Check
- Confirm dates, owners, figures, and milestone names are accurate and current.
- Explain changes from the previous report and connect significant variances to an action or decision.
- Keep sensitive personal, customer, and security information out of the report unless the audience is authorized to receive it.
- Remove all bracketed prompts and ensure every section contains useful content or an explicit `None` / `Not set`.
